- Exact B020: RemoteEdit.valid loops over wallet_ledger coins/issued_run/settled_run and rejects !RushCloudRestore.integer(value, SaveService.MAX_COINS). Missing keys yield null. Maximum is 2,000,000,000. The old log does not distinguish which key failed.
- Trace: SaveService.WALLET_DEFAULTS supplies these counters; local shape validation permits absent keys and load normalizes them. Cloud snapshot copies wallet into meta/main.wallet_ledger. FirestoreCodec encodes integral floats as integerValue and decodes integerValue as int/doubleValue as float. The validator already accepts integral floats; this was not an int-versus-float rejection.
- Narrow compatibility: missing issued_run/settled_run can be reconstructed only if last_started==last_finalized, both valid, receipt matches that completed run (or empty receipt and zero runs), and any supplied wallet counter agrees. No incomplete/ambiguous history is guessed. Valid numbers canonicalize to int. Missing/malformed coins, fractions, negatives, out-of-range values and inconsistent counter evidence still reject. Logs now identify the fixed field name/reason, never values.
- Account A false LOCAL_CHANGED: pending bootstrap snapshots read temporary in-memory defaults; initialization during the request can change their digest. The comparison is bypassed only for authenticated matching UID, remote bootstrap, pending/no local cache, no primary/backup/pending file, no Guest import and no active run. Established or recoverable local saves still get the original comparison; callback generation guards remain.
